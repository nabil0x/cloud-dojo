Q4.1 — VPC anatomy (30 XP)

Phase: Phase 4 — EC2 + VPC + RDS

Concept

A VPC (Virtual Private Cloud) is your own isolated network inside one AWS region, carved out of a CIDR block like 10.0.0.0/16. Every resource that needs an IP address, EC2 instances, RDS databases, load balancers, lives inside one.

Subnets split that block into smaller ranges, and each subnet is pinned to a single Availability Zone, so spreading workloads across AZs means using several subnets. Route tables decide where packets from a subnet go next, and a route to 0.0.0.0/0 through an internet gateway is what makes a subnet "public."

A private subnet has no such route; if it needs outbound internet it reaches through a NAT gateway instead. That split matters because databases belong in private subnets, unreachable from the open internet. A default VPC ships with a public subnet per AZ and an internet gateway already wired up, so beginners can launch something in seconds.

It's a fine place to learn and a poor place to stop thinking. This quest is pure inspection in a real sandbox account, so it costs nothing by itself, but it teaches the map you'll rely on for every later resource. Read it until you can sketch the path from the internet to an instance without looking.

Uses

  • Segment workloads: public subnets for web servers, private subnets for databases and internal services.
  • Shrink blast radius: a compromised public host still can't reach a private database unless a rule allows it.
  • Plan hybrid connectivity to on-prem networks over VPN or Direct Connect using the same CIDR scheme.
  • Lay out multi-tier apps: load balancer in public, app servers in private, RDS deeper still.
  • Avoid surprise bills by seeing where a NAT gateway (hourly + per-GB) would sit before you build one.

Key info

  • Default VPC CIDR is usually 172.31.0.0/16, with one subnet per AZ.
  • Public subnet = its route table has a 0.0.0.0/0 route to an internet gateway (IGW).
  • Private subnet = no IGW route; outbound traffic goes through a NAT gateway, or nowhere.
  • Security groups attach to resources and are stateful; NACLs attach to subnets and are stateless.
  • A subnet lives in exactly one AZ; lose that AZ and you lose the subnet, so spread across AZs.
  • Inspect with the CLI: aws ec2 describe-vpcs, aws ec2 describe-subnets, aws ec2 describe-route-tables, aws ec2 describe-internet-gateways.
  • In a real sandbox account, reading the default VPC is free. Nothing here needs teardown.

Pitfalls

  • Thinking "public subnet" means the instances are public by default; the route table plus the security group decides.
  • Forgetting that NAT gateways bill hourly and per GB processed, often the largest silent cost in a lab.
  • Treating the default VPC as production-ready; it's a convenience, not an architecture.

Done check

Paste the subnet + route-table listing (console screenshot description or CLI describe-subnets output).
