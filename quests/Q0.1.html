Q0.1 — Hello, Docker (10 XP)

Phase: Phase 0 — Docker Foundations

Concept

Docker packages an application and everything it needs into one image, then runs that image as an isolated container. The hello-world image is the smallest possible proof that the whole chain works: the CLI, the daemon, and registry access.

Run it and Docker pulls the image if it's missing, starts a container, lets it print a message, and the container exits. It exists so you can separate "Docker is broken" from "my app is broken" before you write a single Dockerfile. If this one command succeeds, your install is healthy and you can move on with confidence.

Uses

  • Verify a fresh Docker install on a new laptop, server, or CI runner.
  • Confirm the Docker daemon is running after a reboot or an upgrade.
  • Test connectivity to Docker Hub, since the image is pulled from a registry.
  • Check whether sudo or group permissions are needed before real work.
  • Give a five-second health check in docs or onboarding scripts.

Key info

  • docker run hello-world pulls (if missing), creates, starts, prints, and stops.
  • docker version shows the client and the server (daemon) versions separately.
  • docker ps -a lists the now-exited container; it is tiny and safe to leave.
  • Remove it cleanly with docker rm <id>.
  • On Linux, add your user to the docker group: sudo usermod -aG docker $USER, then log out and back in.
  • Once that group step is done, you no longer need sudo for Docker commands.
  • The command exits with code 0; a non-zero code means the smoke test itself failed.
  • This image does nothing else on purpose; it exists only to prove the plumbing.
  • docker run <image> is create plus start plus attach plus print, in one command.
  • Check the exit code with echo $? right after; 0 means success.
  • docker rmi hello-world removes the local image once you're done with it.

Pitfalls

  • "Cannot connect to the Docker daemon" means the daemon isn't running; start Docker Desktop or sudo systemctl start docker.
  • "permission denied" on /var/run/docker.sock means you aren't in the docker group yet.
  • Expecting the container to stay alive: it stops the moment its main process exits.
