# Q0.5 — Layers and cache (20 XP)

**Phase:** Phase 0 — Docker Foundations

## Concept
Every Dockerfile instruction creates a layer, identified by a content hash. When you rebuild, Docker reuses any layer whose instruction and inputs are unchanged, and that reuse is the build cache.

Ordering instructions so slow-changing ones come first makes rebuilds fast: a one-line code edit should only rebuild the last layer. `docker image history` shows each layer and the command that made it, so you can literally watch the cache work. This quest is about noticing that order changes your feedback loop.

## Uses
- Cut CI build time by reusing dependency layers across commits.
- Keep the inner dev loop fast when only app code changes.
- Debug slow builds by spotting a huge or frequently invalidated layer.
- Understand why image pulls are small when only the top layer changed.
- Design Dockerfiles that cooperate with the cache instead of fighting it.

## Key info
- First rebuild with no changes: every layer shows `CACHED` and finishes in a moment.
- Edit `index.html` and rebuild: only the `COPY` layer and anything after it rebuilds.
- Inspect layers: `docker image history dojo-site`.
- Force a full rebuild when needed: `docker build --no-cache -t dojo-site .`.
- Cache is content-based, not time-based; Docker compares hashes, not timestamps.
- Slow-changing instructions (`FROM`, dependency installs) belong at the top.
- Fast-changing instructions (`COPY` app code) belong at the bottom.
- Big layers early make every later change feel slow.
- `docker build` prints `CACHED` per step, the quickest way to read the cache.
- Unchanged Dockerfile plus unchanged context means a near-instant rebuild.
- Only changed top layers transfer when you push and pull between machines.

## Pitfalls
- Editing a file early in the context invalidates every layer after it.
- `COPY . .` before a dependency install means every code change re-installs dependencies.
- Assuming the cache is stale: it only invalidates when the content actually changes, so a changed mirror won't be noticed unless the instruction changes.
