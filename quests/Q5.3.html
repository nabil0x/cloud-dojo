Q5.3 — SageMaker training run (35 XP)

Phase: Phase 5 — Bedrock + SageMaker

Concept

SageMaker is AWS's full machine learning platform, and its training jobs are managed, metered compute: you hand it a script, a dataset, and an instance type, and it hands back metrics and a model artifact. You don't manage the servers; you're billed while the job runs, by instance-hour.

SageMaker Studio (or a notebook instance) is the development environment, and it bills like EC2, so it should be stopped the moment you stop working. That idle notebook is the most common SageMaker cost leak.

JumpStart gives you prebuilt models and notebooks, the fastest route to a fine-tune without writing a training loop; a toy PyTorch script on a tiny dataset works too. The deliverable is simple but complete.

A job that reaches Completed, one metric you actually looked at, and the artifact safely written to S3. Real AWS only, so clean up the notebook instance and any idle compute after.

Uses

  • Fine-tune a prebuilt model on your own labeled data before deploying it.
  • Run reproducible training experiments with metrics tracked centrally.
  • Train on managed GPUs without provisioning or patching a cluster.
  • Produce a model artifact in S3 ready for an endpoint or Batch Transform.
  • Use JumpStart notebooks to skip boilerplate and focus on data and results.

Key info

  • Dev environment: SageMaker Studio or a notebook instance. Stop the notebook instance when idle, it bills like EC2.
  • Job inputs come from S3 (dataset), outputs go back to S3 (model artifact).
  • JumpStart fine-tune is the fastest path; a small script on a tiny dataset is fine for learning.
  • Watch one metric (even a bad loss curve); tracking beats a perfect score here.
  • Check status: aws sagemaker describe-training-job --training-job-name <name> until Completed.
  • Record the artifact S3 path: s3://<bucket>/<job-name>/output/model.tar.gz.
  • Billing: training bills per instance-hour while running; notebook instances bill while running; artifacts bill for S3 storage. Use managed spot to cut cost if available.

Pitfalls

  • Leaving the Studio or notebook instance running after the job, the most common SageMaker cost leak.
  • Forgetting the S3 output path, so you can't find or reuse the artifact later.
  • Submitting a training job on a large instance for a toy dataset, wasting money for no gain.

Done check

Paste the training job status (Completed) + the S3 path of the artifact.
