Q5.2 — Ground it with your data (35 XP)

Phase: Phase 5 — Bedrock + SageMaker

Concept

A raw model only knows its training data, so ask it about your private notes and it will invent an answer. Retrieval-Augmented Generation (RAG) fixes this: retrieve the relevant chunks of your own content, stuff them into the prompt, and let the model generate an answer grounded in them.

Bedrock Knowledge Bases do this managed for you, chunking and embedding your S3 files and searching them at query time. You can also hand-roll the pipeline to see what's actually inside: chunk, embed, search, stuff, generate.

Grounded answers cite the source chunk they used, which is how you prove the model read your data instead of hallucinating. This quest is the difference between a demo that lies and a feature you can trust on private data.

Everything runs on real AWS, so delete the Knowledge Base and its S3 objects when you're finished. The embedding calls and any vector store bill while they exist.

Uses

  • Answer questions over internal docs, course notes, or policies without fine-tuning.
  • Power support bots and search that quote real sources instead of guessing.
  • Keep private data private: retrieval happens in your account, not by retraining the model.
  • Refresh knowledge by updating the source files, not by retraining anything.
  • Hand-roll RAG once to understand what a managed Knowledge Base is doing for you.

Key info

  • Put 2–3 text files (course notes work well) in an S3 bucket.
  • Managed path: create a Bedrock Knowledge Base, point it at the S3 bucket, sync the data source, then query with the retrieve-and-generate API.
  • Hand-rolled path: chunk your files, embed the chunks, embed the question, pick the nearest chunks, and paste them into the prompt.
  • Always cite the source chunk alongside the answer; an uncited answer doesn't prove grounding.
  • Diagnose failures in order: wrong chunks retrieved (search/embedding), right chunks ignored (prompt), stale index (sync pipeline).
  • Billing: embedding and generation calls cost per token, and the vector store may bill for storage, so tear down the Knowledge Base after the quest.

Pitfalls

  • Indexing once and never re-syncing after you edit the source files, so answers go stale.
  • Retrieving chunks but forgetting to actually include them in the prompt, then blaming the model.
  • Deleting the S3 files but leaving the Knowledge Base and vector store running.

Done check

Paste the grounded answer + the source chunk it cited. Ungrounded answers don't count.
