Q4.2 — Launch EC2 + security groups (40 XP)

Phase: Phase 4 — EC2 + VPC + RDS

Concept

EC2 (Elastic Compute Cloud) is renting a virtual machine by the second. You pick an AMI (the OS image), an instance type (the hardware), a key pair (for SSH), and a security group (the firewall). A t3.micro is burstable and free-tier eligible, which makes it the standard learning box.

The security group is where beginners get burned. It's stateful, so return traffic is automatic, but every inbound rule must be explicit. Opening SSH to 0.0.0.0/0 means the entire internet can try to brute-force your box within minutes of launch.

Scoping port 22 to your own IP is the correct habit from day one. User data then lets you bootstrap software at first boot, so you can install a web server and serve a page without logging in by hand.

This quest runs against a real sandbox instance, so it bills while running and must be stopped or terminated when you're done. The rule for the phase holds: if you sleep, it sleeps terminated.

Uses

  • Host a small web server or API endpoint for testing without a managed platform.
  • Run bootstrap scripts (user data) to configure software automatically at first boot.
  • Use as a jump host or bastion to reach private resources like an RDS database.
  • Reproduce production-like networking and firewall behavior in a safe lab.
  • Learn the exact launch flow you'll later automate with Terraform or CloudFormation.

Key info

  • Free-tier eligible: t3.micro (or t2.micro in some regions); verify current terms in your sandbox.
  • Key pair: .pem file, chmod 400 it, then ssh -i key.pem ec2-user@<public-ip>.
  • User data runs once at first boot as root: start with #!/bin/bash, then yum install -y httpd && systemctl start httpd.
  • Security group rules: SSH 22 from your IP only (find it via curl ifconfig.me); HTTP 80 open to 0.0.0.0/0.
  • Find and test: aws ec2 describe-instances, then curl http://<public-ip>.
  • Billing: a running EC2 bills per second; a stopped instance still bills for its EBS volume.
  • Terminate the instance once the quest is verified, and confirm the state is terminated.

Pitfalls

  • Opening SSH to 0.0.0.0/0; scope it to your IP and update the rule when your IP changes.
  • Losing the private key or using the wrong user (ec2-user for Amazon Linux, ubuntu for Ubuntu).
  • Forgetting a stopped instance may get a new public IP on restart, breaking bookmarked addresses.

Done check

Paste the curl of your instance's public IP returning your page + the SG inbound rules.
