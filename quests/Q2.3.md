# Q2.3 — The DNS lesson (30 XP)

**Phase:** Phase 2 — Compose Capstone

## Concept
This quest breaks the app on purpose so the fix sticks.
Inside a container, `localhost` means that container, never your laptop.
So if you set `AWS_ENDPOINT_URL=http://localhost:4566` on the app service, the app tries to reach an emulator running inside itself, finds nothing, and `/s3` fails.
The correct value is `http://emulator:4566`, because Compose gives every service a DNS name equal to its service name on the shared network.
You will edit the env var, rebuild, watch it fail, then set it back, rebuild, and watch it pass.
The lesson is not the typo, it is the reflex: when a container cannot reach a service, ask "localhost from whose perspective?"

## Uses
- Debugging container-to-container connection errors, one of the most common Docker problems.
- Configuring service discovery in a Compose stack today and in Kubernetes later.
- Understanding why a connection works from your laptop but fails from inside a container.
- Building the instinct that a host and a container have different views of the network.
- Explaining the same idea to teammates when a deploy "cannot reach the database".

## Key info
- Break it: set the app's `AWS_ENDPOINT_URL` to `http://localhost:4566` in `compose.yaml`, then `docker compose up -d --build`.
- Fix it: set it back to `http://emulator:4566`, then `docker compose up -d --build`.
- Service DNS rule: a service is reachable at `http://<service-name>:<container-port>` from other services.
- Host access uses the published port, so `http://localhost:4566` works from your laptop.
- Scope the logs to one service while testing: `docker compose logs -f app`.
- Compose creates one default network per project; all its services join it automatically.
- Inspect the network yourself: `docker network inspect phase-02-compose_default`.
- The same rule applies to the emulator: the app reaches it as `emulator`, never `localhost`.

## Pitfalls
- Changing the env var but skipping `--build` or recreation, so the old value is still baked into the running container.
- Editing the port mapping instead of the endpoint. The real error is name resolution, not a missing port.
- Assuming `localhost` is universal. It is always relative to whoever is making the call.
