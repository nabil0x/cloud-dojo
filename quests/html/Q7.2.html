Q7.2 — Pipeline: build + test, red then green (35 XP)

Phase: Phase 7 — CI/CD + ECS

Concept

Continuous integration means every push is built and tested in a clean room that is not your laptop. When the pipeline runs, "works on mine" stops being an excuse: either the tests pass in the clean environment or the build is red. Red is a signal, not a failure of the tool, and it should stop a merge.

A pipeline is just code, usually a YAML file under .github/workflows/, with triggers, jobs, and steps. This quest adds a workflow that checks out the repo, builds the image, and runs unit tests, then you deliberately make it fail once so you see red.

Fixing the cause brings it back to green, and you keep both runs as evidence that the pipeline actually catches problems rather than just passing by luck.

Uses

  • Merge gates: a red check blocks a broken change from reaching main.
  • Clean-room proof: the build runs on a fresh machine every time, not your tuned setup.
  • Fast feedback: failing tests surface in minutes instead of at deploy time.
  • Consistent toolchain: the runner controls the environment, so results repeat.
  • Evidence trail: every red and green run is logged and linkable.

Key info

  • A minimal workflow:

name: ci
on:
  push:
    branches: [main]
jobs:
  build-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: docker build -t dojo-app:ci .
      - run: docker run --rm dojo-app:ci python -m pytest -q
  • Triggers live under on:; each job runs on a fresh runs-on machine.
  • Read a failed log top-down: the first real error is usually the only one that matters.
  • Pin action versions (@v4, not a floating ref) so a surprise release cannot break your build.

Pitfalls

  • Testing only locally and assuming CI agrees. The clean room finds missing files and env differences.
  • Logging secrets or tokens into build output, which then sit in the run history.
  • Using unpinned action versions, so the pipeline changes behavior without a commit.

Done check

paste the red run URL/title + the green run URL/title. Both are required evidence.
