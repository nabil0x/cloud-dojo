Q6.3 — State: list, show, import (30 XP)

Phase: Phase 6 — Terraform IaC

Concept

Terraform does not guess what it owns. It keeps a state file (terraform.tfstate) that maps each block in your code to a real resource ID in the cloud. Lose the state and Terraform forgets those resources exist, so it tries to create duplicates.

This quest teaches three state operations. state list shows every resource Terraform tracks. state show dumps one resource's full attributes as JSON, which is where you find things like the bucket ID. import adopts a resource you created by hand (here, an SQS queue made with the AWS CLI) into state, so Terraform starts managing it.

After a clean import, a re-plan reports zero changes, proving code and reality now agree.

Uses

  • Adopting existing infra: bring a hand-made queue, bucket, or database under Terraform without recreating it.
  • Incident debugging: state show reveals the exact ID and config Terraform believes is live.
  • Auditing ownership: state list answers "what does this config actually manage?"
  • Moving resources: state mv renames an address without destroying anything.
  • Refactoring safety: understand state before you rename blocks or split modules.

Key info

  • Create a queue by hand, then import it into a matching block:

aws --endpoint-url=http://localhost:4566 sqs create-queue --queue-name dojo-queue

# in main.tf: resource "aws_sqs_queue" "dojo" { name = "dojo-queue" }

terraform import aws_sqs_queue.dojo \
  http://localhost:4566/000000000000/dojo-queue
  • terraform state list shows addresses like aws_s3_bucket.dojo and aws_sqs_queue.dojo.
  • terraform state show aws_s3_bucket.dojo prints all attributes, including id.
  • Import needs the config block already present; it does not generate HCL for you.
  • A clean result is No changes. Your infrastructure matches the configuration.

Pitfalls

  • Hand-editing terraform.tfstate. It holds resource mappings and plaintext secrets; a bad edit corrupts state.
  • Importing when the block's attributes do not match reality, so the next plan wants to change or destroy the resource.
  • Working in the wrong directory or backend and importing into (or destroying) the wrong state.

Done check

paste state list (both resources) + the empty No changes plan.
