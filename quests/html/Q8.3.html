Q8.3 — Hardened API: auth, throttle, CORS (40 XP)

Phase: Phase 8 — RAG Capstone

Concept

An endpoint that answers questions is also an endpoint that spends money, so it has to be defended. This quest puts a Lambda behind an API Gateway HTTP API and hardens the front door.

The Lambda does the orchestration: take the query, retrieve from the knowledge base, call the model, and return JSON with citations. The gateway adds the protections: an authorizer (JWT or IAM) on every route so anonymous callers cannot burn your budget, throttling so one abusive client cannot, CORS locked to exact origins, and input validation with a max length because tokens are money.

Timeouts matter too and they cascade: the gateway has a hard limit, the function can run far longer, and the model call sits inside that. Set each one deliberately or the defaults will surprise you mid-demo.

Uses

  • Auth gating: only authorized callers reach the retrieval and model spend.
  • Abuse control: per-route rate limits cap the damage from a runaway client.
  • Browser safety: exact-origin CORS lets your frontend call the API without opening it to the world.
  • Cost protection: input length caps stop a giant prompt from multiplying token cost.
  • Predictable failures: deliberate timeouts fail cleanly instead of hanging the demo.

Key info

  • Handler shape: parse the query, validate length, retrieve from the KB, generate with the model, return { "answer": ..., "citations": [...] }.
  • Attach an authorizer and set limits on the route:

# JWT or IAM authorizer on every route; then:
aws apigatewayv2 update-stage --api-id <id> --stage-name prod \
  --default-route-settings '{"ThrottlingBurstLimit":20,"ThrottlingRateLimit":10}'
  • CORS: use exact origins. Never combine * with credentials.
  • Timeout cascade to set on purpose: gateway (roughly 29 seconds max) below the function timeout, and the function timeout below what the model call can take.
  • Prove the gate works: an authorized curl returns a cited answer, an unauthorized one returns 401 or 403.
  • A JWT or IAM authorizer ties back to Track T; the IAM path pays off here.

Pitfalls

  • No authorizer on a route, so anyone with the URL spends your Bedrock budget.
  • CORS set to * while sending credentials, which browsers reject and which leaks to any origin.
  • No max input length, so a single huge prompt multiplies token cost and slips past throttle limits.

Done check

paste curl of the live endpoint returning a cited answer + the auth-rejected curl (401/403) proving the gate works.
