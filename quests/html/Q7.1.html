Q7.1 — Prod-ready image + ECR (25 XP)

Phase: Phase 7 — CI/CD + ECS

Concept

An image that runs on your laptop is not yet an image you can ship. Production images are pinned, small, safe, and observable.

Pinning means an exact base tag like python:3.13-slim instead of latest, so a rebuild months later still gets the same base. Safety means a non-root USER, so a container escape is not a root escape. Size and hygiene mean a .dockerignore that keeps .git and secrets out of the build context. Observability means a HEALTHCHECK the orchestrator can read.

Then you publish the image to Amazon ECR, the private registry ECS will pull from. This quest hardens the Phase 2 app and pushes a :v1 tag, proving you can get an image into a real registry.

Uses

  • Repeatable deploys: a pinned, immutable tag means the same bits everywhere.
  • Smaller attack surface: non-root plus a lean context cuts what a compromise can reach.
  • Faster ships: multi-stage builds drop build tooling from the final image.
  • Registry workflow: ECR is where ECS and your pipeline pull images from.
  • Health-based recovery: HEALTHCHECK lets the platform replace a sick container.

Key info

  • A hardened Dockerfile skeleton:

FROM python:3.13-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
USER 1001
HEALTHCHECK CMD curl -f http://localhost:8000/health || exit 1
CMD ["python", "app.py"]
  • Create the repo and push:

aws ecr create-repository --repository-name dojo-app --region us-east-1
aws ecr get-login-password --region us-east-1 \
  | docker login --username AWS --password-stdin <acct>.dkr.ecr.us-east-1.amazonaws.com
docker build -t dojo-app:prod .
docker tag dojo-app:prod <acct>.dkr.ecr.us-east-1.amazonaws.com/dojo-app:v1
docker push <acct>.dkr.ecr.us-east-1.amazonaws.com/dojo-app:v1
  • The push prints an image digest; that digest is the immutable proof of what shipped.

Pitfalls

  • Using latest as the base or the deploy tag. It moves under you and makes rollbacks meaningless.
  • Running as root because the base image defaults to it, and forgetting to create a USER.
  • Letting .git, .env, or credentials into the context because there is no .dockerignore.

Done check

paste the push digest + the ECR console/CLI image listing.
