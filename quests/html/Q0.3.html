Q0.3 — Lifecycle: ports, logs, stop/rm (15 XP)

Phase: Phase 0 — Docker Foundations

Concept

A container has a lifecycle: it's created, started, runs, stops, and is removed. Reading logs and inspecting state is how you operate containers, not just launch them. Port mapping is what makes one reachable, and -p 8080:80 sends host traffic on 8080 into the container's port 80.

This quest drills the commands you'll type dozens of times a day. stop frees the process gracefully; rm deletes the writable layer for good. Nginx is the perfect subject because it logs every request and serves a page you can see in a browser.

Uses

  • Debug a misbehaving service by reading its stdout and stderr.
  • Serve a local page on a chosen port during development.
  • Free a port by finding and stopping the container that owns it.
  • Clean up stopped containers so docker ps -a stays readable.
  • Practice the exact commands you'll use under a Compose stack later.

Key info

  • Run nginx on host port 8080: docker run -d --name dojo-web -p 8080:80 nginx.
  • -p HOST:CONTAINER; the container port is what the app listens on inside.
  • docker logs dojo-web prints stdout/stderr; add -f to follow live.
  • docker stop dojo-web sends SIGTERM, then SIGKILL after a grace period.
  • docker rm dojo-web deletes the container; the image stays.
  • docker ps shows running containers; docker ps -a includes stopped ones.
  • Open http://localhost:8080 in a browser, then run the commands in order.
  • docker rm -f stops and removes in one step when you're in a hurry.
  • docker inspect dojo-web shows IP, mounts, and environment in full detail.
  • docker exec -it dojo-web sh opens a shell inside a running container.
  • docker start dojo-web restarts a stopped container without recreating it.

Pitfalls

  • "Port is already allocated" means something else owns host 8080; find it with docker ps or lsof -i :8080.
  • Running docker rm on a live container fails; stop it first or use docker rm -f.
  • Editing files inside a running container feels permanent but isn't: that writable layer dies with rm.

Done check

docker ps -a showing it gone, plus one log line pasted.
