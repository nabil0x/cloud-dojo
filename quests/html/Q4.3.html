Q4.3 — AMIs, EBS, stop/start billing lesson (25 XP)

Phase: Phase 4 — EC2 + VPC + RDS

Concept

An AMI (Amazon Machine Image) is a snapshot template: an OS plus whatever software you installed. Launch from it and you get an identical machine, which is how reproducible infrastructure starts. Bake a golden image once, then clone it on demand.

EBS (Elastic Block Store) is the network disk attached to your instance, and it survives independently of the instance. That independence is the whole billing lesson: when you stop an instance, compute charges pause but the EBS volume keeps existing and keeps billing.

Terminating the instance can delete the volume only if that flag is set; otherwise it lingers as an unattached volume, quietly costing money. Snapshots behind an AMI cost storage too, and nobody sees them in the instance list.

This quest makes you feel the distinction by stopping, imaging, terminating, and re-launching. Real sandbox rules apply, so the original must be terminated after the clone works and any leftover volume or snapshot deleted.

Uses

  • Bake a golden AMI once (patched OS + your app) and launch identical clones on demand.
  • Scale out: launch N instances from one AMI behind a load balancer.
  • Recover a machine by launching a fresh instance from an image of a known-good state.
  • Move a configured instance across AZs by imaging it and relaunching elsewhere.
  • Understand why "I stopped it, why am I still billed?" is the most common first cloud bill surprise.

Key info

  • Stop = compute off, EBS still billed. Terminate = compute gone, root volume deleted by default (data volumes may persist).
  • Create an AMI: aws ec2 create-image --instance-id <id> --name my-image --no-reboot (or console: Instance state → Image and templates → Create image).
  • Launch the clone from the AMI: aws ec2 run-instances --image-id <ami-id> ....
  • Track it: aws ec2 describe-images --owners self, aws ec2 describe-volumes.
  • Still billed while stopped: the EBS volume (per GB-month). Snapshots also bill per GB-month.
  • Deregister unused AMIs and delete their snapshots when you're done, or they bill forever.
  • The original must be terminated after the clone is confirmed, and leftover volumes or snapshots deleted.

Pitfalls

  • Assuming "stopped" means "not billed"; EBS, Elastic IPs, and snapshots all survive a stop and bill.
  • Creating an AMI but never deleting the snapshots behind it; images and their snapshots cost storage.
  • Leaving the original instance running after the clone works, doubling compute spend.

Done check

Paste describe-instances showing the clone running + one sentence on what still bills while stopped.
