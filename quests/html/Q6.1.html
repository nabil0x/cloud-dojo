Q6.1 — First config: provider + bucket (30 XP)

Phase: Phase 6 — Terraform IaC

Concept

Terraform is infrastructure as code: you describe the resources you want in text files, and Terraform makes reality match that description. Instead of clicking around a cloud console, you write a provider block (which cloud, and where) plus one or more resource blocks (what to create). The golden loop is write, terraform init, terraform plan, read the plan, terraform apply.

In this quest the AWS provider points at the local emulator by overriding its endpoints to http://localhost:4566 and using fake credentials, so nothing costs money. One aws_s3_bucket proves the whole loop works end to end. Every later quest is just more resources in the same pattern.

Uses

  • Reproducible environments: the same config builds dev, staging, and prod.
  • Infrastructure review: plan is a diff you can read and approve before it runs.
  • Onboarding: git clone plus terraform apply replaces a wiki page of setup steps.
  • Emulator-first development: one config targets localhost now and real AWS later by swapping endpoints.
  • Drift detection: re-running plan reveals anything changed outside of code.

Key info

  • terraform init downloads the AWS provider and creates .terraform/.
  • terraform plan prints what would change; terraform apply runs it.
  • The endpoint override is the emulator trick:

provider "aws" {
  region                      = "us-east-1"
  access_key                  = "test"
  secret_key                  = "test"
  skip_credentials_validation = true
  skip_requesting_account_id  = true
  skip_metadata_api_check     = true
  endpoints {
    s3 = "http://localhost:4566"
  }
}

resource "aws_s3_bucket" "dojo" {
  bucket = "dojo-first-bucket"
}
  • Read the plan line by line: the summary lists creates, changes, and destroys.
  • Success looks like Apply complete! Resources: 1 added, 0 changed, 0 destroyed.

Pitfalls

  • Running apply without reading plan. The plan is the whole point; skipping it is how people create 40 NAT gateways.
  • Using fake credentials without the skip_* flags. Real AWS validation rejects them and plan fails cryptically.
  • Forgetting the endpoints override and accidentally talking to real AWS, or hanging on a network call.
