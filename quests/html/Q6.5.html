Q6.5 👹 Boss: destroy + clean proof (30 XP)

Phase: Phase 6 — Terraform IaC

Concept

Creating infrastructure is the easy half; owning its cost means being able to remove it cleanly. terraform destroy reads the same state file and deletes everything Terraform manages, in reverse dependency order. You type yes by hand for a reason: it is a deliberate, irreversible act, and feeling that friction is the point.

This boss quest has two halves. First you destroy the emulator stack and prove, through the CLI, that the bucket, queue, topic, and table are gone. Second you run plan against the real sandbox for the same config, with no apply, and read what would be created and what it would cost.

That gap between "would create" and "did create" is the discipline this phase is teaching.

Uses

  • Cost hygiene: tear down learning stacks so nothing bills in the background.
  • Safe experiments: destroy and re-apply to prove a config rebuilds from scratch.
  • Pre-deploy review: a read-only sandbox plan shows cost exposure before you commit.
  • Handover: destroy gives a clean slate for the next learner or environment.
  • Trust: dry-run plans make production changes predictable.

Key info

  • terraform destroy prints the plan, then asks for yes before deleting.
  • Verify removal with the CLI:

aws --endpoint-url=http://localhost:4566 s3 ls
aws --endpoint-url=http://localhost:4566 sqs list-queues
aws --endpoint-url=http://localhost:4566 sns list-topics
aws --endpoint-url=http://localhost:4566 dynamodb list-tables
  • For the sandbox half, point the provider at real AWS and run terraform plan only. Never apply here.
  • A sandbox plan reports a count and the resources it would add, so you can size the cost before spending.
  • Success looks like Destroy complete! Resources: N destroyed.

Pitfalls

  • Running destroy against the wrong backend or workspace and wiping something you meant to keep.
  • Testing the sandbox with apply instead of plan, which starts real billing.
  • Leaving resources created by hand (outside Terraform) behind, so "clean" is not actually clean.

Done check

paste Destroy complete! + the sandbox plan's resource count. Par: emulator empty, sandbox untouched.
