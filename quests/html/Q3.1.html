Q3.1 — Build a Lambda image (40 XP)

Phase: Phase 3 — Lambda Container Images

Concept

Lambda normally runs a zip of code, but it also runs containers.

You package a function as a Docker image that starts from AWS's own Lambda base image, public.ecr.aws/lambda/python:3.13.

That base supplies the Runtime Interface Client, the bridge between Lambda's runtime and your handler, so your Dockerfile only needs to copy the handler and set the CMD to the handler name.

The function itself is a small Python file with def handler(event, context): ....

When you rebuild after editing only the handler, Docker reuses the cached base and dependency layers and rebuilds just the last layer, which is fast.

That layering behavior is the point: the same Docker skills from Phase 0 now ship serverless code.

Uses

  • Shipping functions with large or native dependencies that exceed the zip size limit.
  • Reusing an existing container toolchain and base image for serverless workloads.
  • Keeping build times low by putting stable dependencies in early layers.
  • Porting a containerized service to serverless with minimal changes.
  • Pinning the exact runtime version that your tests were written against.

Key info

  • Create lambda/ with a handler file, for example def handler(event, context): return {"ok": True}.
  • Start the Dockerfile with FROM public.ecr.aws/lambda/python:3.13.
  • Copy the handler and set CMD ["app.handler"] to name the entry point.
  • Build: docker build -t dojo-lambda .
  • Inspect layers: docker image history dojo-lambda
  • Watch only the last layers rebuild when you edit the handler and nothing else.
  • The base image is large, so keep it as the first line to preserve the cache.

Pitfalls

  • Putting COPY . . before installing dependencies, which invalidates the cache on every code edit.
  • Forgetting that the base image already provides the runtime, so installing your own breaks the contract.
  • Using the wrong handler name in CMD. It must match file.function.

Done check

paste docker images | grep dojo-lambda + docker image history dojo-lambda --format '{{.CreatedBy}}' (first 5 lines).
