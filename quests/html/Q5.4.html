Q5.4 — Deploy an endpoint, then kill it (25 XP)

Phase: Phase 5 — Bedrock + SageMaker

Concept

A SageMaker real-time endpoint is a persistent, load-balanced inference server. You deploy a model artifact to it, then send requests and get predictions back with predictable latency. For a live app, that's exactly what you want.

The catch is the billing model: an endpoint bills per instance-hour for as long as it *exists*, whether or not anyone calls it. An idle endpoint costs exactly as much as a busy one, which is why this quest makes you deploy and then delete in the same session.

The full loop is deploy, invoke, record latency and output, then delete the endpoint and its endpoint configuration immediately. That discipline is the point of the quest, not a formality.

For offline inference where real-time isn't needed, Batch Transform is the cheaper sibling; know its name and reach for it when latency doesn't matter. This is real AWS, and an endpoint left running fails the quest retroactively.

Uses

  • Serve live predictions to an app that needs low-latency responses.
  • A/B test or canary a new model version behind the same API.
  • Demo a trained model to stakeholders with a real invocation.
  • Measure production-like latency and throughput before committing to a design.
  • Contrast with Batch Transform to decide whether you need a persistent endpoint at all.

Key info

  • Deploy the artifact from Q5.3 to the smallest instance that fits the model.
  • Invoke it: aws sagemaker-runtime invoke-endpoint --endpoint-name <name> --body <payload> out.json.
  • Record the response and the latency (end-to-end time from request to reply).
  • Delete, immediately: aws sagemaker delete-endpoint --endpoint-name <name>, then delete the endpoint configuration.
  • Billing: per instance-hour while the endpoint exists, idle or not, so deletion is the point.
  • Batch Transform (offline, no persistent endpoint) is cheaper whenever real-time isn't required.
  • Confirm the endpoint is gone: aws sagemaker list-endpoints should not show it.

Pitfalls

  • Walking away with the endpoint running; an idle endpoint still bills every hour and fails this quest.
  • Deleting the endpoint but leaving the endpoint configuration or model object behind unnecessarily.
  • Reaching for a real-time endpoint when Batch Transform would do, paying for idle pumps.

Done check

Paste the invocation output + the endpoint-deleted confirmation. An endpoint left running fails this quest retroactively.
