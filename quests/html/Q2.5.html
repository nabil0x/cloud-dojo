Q2.5 — Boss: full rebuild loop (25 XP)

Phase: Phase 2 — Compose Capstone

Concept

This is the boss fight: tear the whole stack down and bring it back from nothing.

docker compose down -v stops and removes every container and, because of -v, the named volumes too.

That means your emulator data is wiped, so "it works on my machine" is no longer a hiding place.

From a clean slate you run docker compose up -d --build, re-seed, and verify both /health and /s3.

Doing this under three minutes is the par.

The real skill is the loop itself: down, up, seed, verify. If you can run that loop confidently, you can reproduce any state your stack can reach, which is what makes debugging and onboarding fast.

Uses

  • Proving a stack rebuilds cleanly from zero, the strongest test of a reproducible dev environment.
  • Onboarding: a new teammate runs one loop and has a working environment.
  • Recovering when local state gets corrupted or inconsistent.
  • Timing yourself to build muscle memory for the rebuild cycle.
  • Catching hidden dependencies on leftover volumes before they reach CI.

Key info

  • Nuke everything, including volumes: docker compose down -v
  • Rebuild and start: docker compose up -d --build
  • Re-seed from the host: bash ../shared/seed.sh
  • Verify: curl localhost:8080/health and curl localhost:8080/s3
  • Par time is under 3 minutes for the whole loop.
  • down without -v keeps volumes and their data. The -v is what makes this a true reset.
  • Confirm a clean slate first: docker compose ps should show no running services.

Pitfalls

  • Forgetting -v and getting old data back, so the "rebuild" was not actually clean.
  • Skipping the re-seed, then finding /s3 empty on a correctly working stack.
  • Running the commands out of order, for example checking /s3 before the app has finished starting.

Done check

paste all three outputs in order. Time yourself — under 3 minutes is the par.
