Q0.6 👹 Boss: custom port + name (20 XP)

Phase: Phase 0 — Docker Foundations

Concept

The boss combines everything from Phase 0: clean up old containers, re-run the emulator under your own name, and prove that port mapping is a deliberate choice. The emulator always listens on 4566 inside the container; the host port is whatever you map to it.

Mapping host 4570 to container 4566 means localhost:4570 reaches the emulator while localhost:4566 is now empty. This separation of internal port from host port is the single most useful Docker skill, and it's the one beginners get backwards most often. Prove both sides of the mapping explicitly and you own the concept.

Uses

  • Run several emulators at once by giving each its own host port.
  • Avoid port conflicts with other tools already using the default port.
  • Give a container a memorable name so scripts don't chase random IDs.
  • Prove a container is reachable on exactly one intended port.
  • Practice the teardown-and-restart cycle you'll repeat all course.

Key info

  • Clean up first: docker ps -a, then docker rm -f <names>.
  • Start on a custom host port and your own name: docker run -d --name <your-name> -p 4570:4566 ministackorg/ministack.
  • Prove the new mapping: curl -s http://localhost:4570/_ministack/health.
  • Prove the old port is empty: curl -s http://localhost:4566/_ministack/health fails or returns nothing.
  • Inspect the mapping: docker ps --format '{{.Names}} {{.Ports}}'.
  • The container port stays 4566; only the host side changes.
  • -p HOST:CONTAINER is always in that order.
  • The container name is also its DNS name on a user-defined network (Q1.6).
  • Give it your own name, for example --name ada-emu -p 4570:4566.
  • A wrong-side mapping still runs; it just listens where you didn't expect.
  • Confirm with docker ps --format '{{.Names}} {{.Ports}}' before declaring success.

Pitfalls

  • Reversing the mapping (-p 4566:4570) publishes the wrong side, so nothing answers on the port you expected.
  • Leaving the old dojo-emu running, so 4566 still responds and the "empty port" proof fails.
  • Assuming the app itself changed ports: the emulator still listens on 4566 internally no matter what you map.

Done check

curl outputs for both ports + docker ps --format '{{.Names}} {{.Ports}}'.
