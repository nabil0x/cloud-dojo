Q1.3 — DynamoDB table + CRUD (30 XP)

Phase: Phase 1 — First AWS Services

Concept

DynamoDB is a NoSQL key-value and document store. Every table needs a partition key, which decides which storage node owns each item, and can optionally have a sort key to order items inside a partition.

Reads come in three shapes: get-item fetches one key fast, query reads one partition in sorted order, and scan reads the whole table. With PAY_PER_REQUEST you pay per operation instead of reserving capacity, which is ideal while learning. The CRUD cycle here is the same one every application will use.

Uses

  • Store user profiles, sessions, and shopping carts at scale.
  • Back serverless APIs where Lambda reads and writes items.
  • Track game state, IoT readings, or device metadata.
  • Serve low-latency lookups without running a database server.
  • Model flexible documents whose fields vary between items.

Key info

  • Create: aws --endpoint-url=http://localhost:4566 dynamodb create-table --table-name Dojo --attribute-definitions AttributeName=id,AttributeType=S --key-schema AttributeName=id,KeyType=HASH --billing-mode PAY_PER_REQUEST.
  • Put: dynamodb put-item --table-name Dojo --item '{"id":{"S":"1"},"name":{"S":"ada"}}'.
  • Get: dynamodb get-item --table-name Dojo --key '{"id":{"S":"1"}}'.
  • Scan: dynamodb scan --table-name Dojo.
  • Delete: dynamodb delete-item --table-name Dojo --key '{"id":{"S":"1"}}'.
  • Attribute values are typed wrappers: {"S":"text"} for string, {"N":"42"} for number.
  • --billing-mode PAY_PER_REQUEST is the on-demand option with no capacity planning.
  • List tables with dynamodb list-tables to confirm creation.
  • A sort key, when present, is added with a second KeyType=RANGE entry.
  • dynamodb describe-table --table-name Dojo shows the key schema after creation.
  • --return-consumed-capacity reports how much capacity each call used.

Pitfalls

  • Mixing up attribute types, like passing {"N":...} where a string is expected, fails the write.
  • Using scan in production; it reads the entire table and gets expensive fast.
  • Picking a low-cardinality partition key concentrates all traffic on one node and throttles.
