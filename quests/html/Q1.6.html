Q1.6 — Bridge DNS: containers talking (15 XP)

Phase: Phase 1 — First AWS Services

Concept

Containers on the same user-defined bridge network resolve each other by name. That means one container can reach the emulator at http://emulator:4566 instead of an IP that changes on every restart.

From your host, the same service is localhost:4566. This host-versus-container distinction is the single most important networking idea in the course, and it's why Compose files use service names as hostnames. Get this right and multi-container apps stop being mysterious.

Uses

  • Connect a worker container to an emulator container by name.
  • Run app plus database plus cache on one private network.
  • Recreate containers freely without updating hardcoded IPs.
  • Replicate a production service mesh on your laptop.
  • Give each team a network name instead of memorized addresses.

Key info

  • Create the network: docker network create dojo-net.
  • Attach the emulator: docker run -d --name emulator --network dojo-net -p 4566:4566 ministackorg/ministack.
  • Start a second container on it: docker run --rm -it --network dojo-net curlimages/curl sh.
  • Reach the emulator by name from inside: curl http://emulator:4566/_ministack/health.
  • The name is the --name value, not the image name.
  • Only containers on the same user-defined network can resolve each other.
  • The rule to memorize: host uses localhost:4566, a container uses <name>:4566.
  • A container keeps its host published port too, so the host path still works.
  • docker network inspect dojo-net lists which containers are attached.
  • docker network connect attaches an already-running container to the network.
  • Name resolution only works on a user-defined network, never the default bridge.

Pitfalls

  • The default bridge network doesn't do name resolution; always create your own network.
  • Using localhost from inside a container points at that container itself, not the host.
  • A container can't share another's filesystem just by joining a network; only the network is shared.

Done check

paste the successful curl http://<name>:4566/_ministack/health from inside the second container.
