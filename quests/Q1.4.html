Q1.4 — Volumes: survive a restart (30 XP)

Phase: Phase 1 — First AWS Services

Concept

A container's writable layer dies with the container, so any data the emulator stores inside it vanishes on restart. A named volume lives outside the container lifecycle and is mounted into a path inside, so the data survives stop, rm, and re-run.

This quest proves the difference empirically: lose your data once on purpose, then keep it with a volume. The lesson is simple and it applies forever: containers are disposable, data is not. Every stateful service you containerize later depends on getting this right.

Uses

  • Persist a local database across container restarts.
  • Keep uploaded files and seeds when rebuilding an emulator.
  • Share data between two containers at the same time.
  • Back up and restore a volume deliberately, not accidentally.
  • Separate disposable app code from durable state in every stack.

Key info

  • Without a volume, restarting the emulator loses every bucket and table.
  • Mount a named volume at run time: docker run -d --name dojo-emu -p 4566:4566 -v dojo-data:/var/lib/localstack ministackorg/ministack.
  • Mounting syntax is -v <volume-name>:<path-inside-container>.
  • Re-seed the emulator: bash shared/seed.sh.
  • Restart it, then confirm data is still there: aws --endpoint-url=http://localhost:4566 s3 ls shows dojo-bucket.
  • List volumes with docker volume ls.
  • Delete a volume on purpose with docker volume rm dojo-data.
  • The emulator's data path must match the mount target, or persistence silently fails.
  • docker volume inspect dojo-data shows where on the host the data really lives.
  • A bind mount (-v /host/path:/path) is the alternative for a specific host directory.
  • Re-seeding is safe to re-run when the data is already present.

Pitfalls

  • Mounting the volume at the wrong path sends data to the writable layer anyway, so it still vanishes.
  • docker compose down -v deletes named volumes; that's the deliberate nuke, not a normal stop.
  • Removing the container but forgetting the volume name breaks the link and starts you from empty.

Done check

paste s3 ls after the second restart showing dojo-bucket.
