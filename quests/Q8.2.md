# Q8.2 — Data + retrieval, 5-question eval (40 XP)

**Phase:** Phase 8 — RAG Capstone

## Concept
In a retrieval-augmented system, retrieval quality is the product. The model can only ground its answer in what you retrieve, so if the wrong chunks come back, no amount of prompt tuning saves the answer.

This quest builds the data half: curate at least ten real documents (course notes, docs, papers, not filler) into S3, then create a Bedrock Knowledge Base over that bucket to index and retrieve them.

Chunking matters more than the embedding model choice. Chunks that are too large dilute the signal; too small and they lose context. A sane starting range is 300 to 800 tokens with overlap.

Then you prove quality with a five-question eval set, graded honestly, each answer citing the relevant chunk. Fewer than four of five grounded means the retrieval needs rework, not extra XP.

## Uses
- Grounded answers: the bot answers from your documents instead of guessing.
- Eval discipline: a small, honest question set beats vibes when judging quality.
- Metadata filtering: source, date, and doc type narrow search to the right set.
- Regression testing: rerun `eval.md` after every change to catch retrieval drift.
- Domain adoption: point the same pipeline at a new corpus and re-evaluate.

## Key info
- Put real documents in the bucket, then build the knowledge base over it:

```bash
aws s3 cp ./docs s3://dojo-rag-docs --recursive
aws bedrock-agent create-knowledge-base --cli-input-json file://kb.json
aws bedrock-agent start-ingestion-job --knowledge-base-id <kb> \
  --data-source-id <ds>
```

- Chunking start point: 300 to 800 tokens with overlap; too big dilutes, too small loses context.
- Keep the eval in the repo as `eval.md` so future-you reruns it after changes.
- Record each pair as: question, expected source, actual answer, cited chunk, pass or fail.
- Grading bar: at least 4 of 5 must be grounded in a cited source.

## Pitfalls
- Filling S3 with lorem ipsum or unrelated text. The eval will expose it, and so will a reviewer.
- Choosing chunk sizes by default instead of testing, so retrieval returns near-miss context.
- Grading honestly on your own questions. A generous pass now means a broken demo later.
