# Q4.4 — RDS Postgres, scoped access (30 XP)

**Phase:** Phase 4 — EC2 + VPC + RDS

## Concept
RDS (Relational Database Service) runs Postgres (or MySQL, and others) for you: patching, backups, snapshots, and optional Multi-AZ failover are managed. You still own instance sizing, storage growth, credential rotation, and, critically, network access.

A database should never be publicly accessible. The safe pattern is to put it in a private subnet and let only your application reach it. Access control between AWS resources is done with security-group references, not IP addresses.

The RDS security group allows inbound `5432` from the EC2 instance's security group. That SG-to-SG rule means "only machines wearing this badge may connect," and it keeps working even as instance IPs change. Never open a database port to `0.0.0.0/0`.

This quest uses a real `db.t3.micro`, which bills per hour while it exists, so it must be deleted before you move on. Skip the final snapshot for practice data.

## Uses
- Back a web app or API with managed Postgres and automated backups.
- Store structured data (users, orders, events) without running your own database server.
- Enforce least-privilege networking: app tier talks to DB, nothing else can.
- Practice the SG-to-SG pattern that recurs in every AWS architecture you'll build.
- Test schema migrations and queries against a production-like engine.

## Key info
- Free-tier eligible: `db.t3.micro`, 20 GB storage (verify current terms in your sandbox).
- Set **Public access = No** and place it in a private or default-VPC subnet.
- RDS security group inbound rule: type PostgreSQL, port `5432`, source = the **EC2 security group ID** (e.g. `sg-0abc...`), never a CIDR like `0.0.0.0/0`.
- Connect from the EC2 box: `psql -h <rds-endpoint> -U <user> -d <dbname>`.
- Then: `CREATE TABLE notes (id serial primary key, body text);` and `INSERT INTO notes (body) VALUES ('hello');`.
- Verify: `SELECT * FROM notes;` and paste the output.
- Billing: RDS bills per instance-hour while it exists (even idle) plus storage. Delete the instance when done.

## Pitfalls
- Marking the database publicly accessible or allowing `0.0.0.0/0` on port 5432.
- Referencing an IP instead of the EC2 security group, so connections break when the IP changes.
- Forgetting the RDS security group must allow the app's SG on the DB port; this is the classic "app can't reach DB" outage.
