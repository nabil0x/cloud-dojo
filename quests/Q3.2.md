# Q3.2 — Push to the local ECR (40 XP)

**Phase:** Phase 3 — Lambda Container Images

## Concept
A function that lives only on your laptop is not a function.
Lambda pulls images from ECR, the private container registry inside AWS, so the next step is to get your image into a registry.
The flow is universal: create a repository, authenticate the Docker client, tag the image for that repository, and push.
On the emulator, ECR is served locally, and the registry address looks like `localhost.localstack.cloud:4510/<repo>`.
The `docker push` output ends with an immutable digest, a `sha256:...` value that identifies the exact bytes you uploaded.
Tags like `:latest` are mutable pointers that move; the digest never does, which is why the done check asks for it.

## Uses
- Storing container images privately inside your AWS account.
- Feeding Lambda and ECS with a versioned, immutable image reference.
- Scanning images for vulnerabilities and applying lifecycle policies.
- Reproducing the same build-and-push flow against a local registry for testing.
- Sharing one image across many services without rebuilding it.

## Key info
- Create the repository: `aws --endpoint-url http://localhost:4566 ecr create-repository --repository-name dojo-lambda`
- Tag for the local registry: `docker tag dojo-lambda localhost.localstack.cloud:4510/dojo-lambda:latest`
- Log in and push following the emulator's ECR instructions.
- Image URI shape: `<registry>/<repo>:<tag>`
- The push output's final line is a `digest:` value, the immutable identity of the image.
- On LocalStack the registry host is `localhost.localstack.cloud:4510`.
- List what you pushed: `aws --endpoint-url http://localhost:4566 ecr list-images --repository-name dojo-lambda`

## Pitfalls
- Forgetting to tag with the registry hostname, so `docker push` tries Docker Hub instead.
- Chasing a moving `:latest` tag in production instead of pinning a digest.
- Not authenticating the Docker client before pushing, which fails with an auth error.

## Done check
paste the push output's final `digest:` line.
