# Q1.5 — Env vars: the universal switch (15 XP)

**Phase:** Phase 1 — First AWS Services

## Concept
Every CLI or SDK call needs three things: an endpoint, credentials, and a region. Instead of passing them on every command, you export them once as environment variables and the CLI picks them up automatically.

`AWS_ENDPOINT_URL` redirects all services to the emulator, so your commands read clean with no `--endpoint-url` flag. Precedence runs from explicit flags down to env vars, then config files, then defaults. This is exactly how you switch the same code between the emulator and real AWS without rewriting it.

## Uses
- Keep long CLI sessions short by exporting the endpoint once.
- Point the same app at the emulator in dev and real AWS in prod.
- Feed endpoint and credentials to SDKs without hardcoding them.
- Configure CI jobs that run against a local emulator.
- Override a single service's endpoint without touching the others.

## Key info
- Export the endpoint: `export AWS_ENDPOINT_URL=http://localhost:4566`.
- Fake credentials: `export AWS_ACCESS_KEY_ID=test` and `export AWS_SECRET_ACCESS_KEY=test`.
- Region: `export AWS_DEFAULT_REGION=us-east-1`.
- Then a plain `aws s3 ls` hits the emulator with no endpoint flag.
- Per-service override exists: `AWS_ENDPOINT_URL_S3`, `AWS_ENDPOINT_URL_DYNAMODB`, and so on.
- Precedence order: explicit flag, then env var, then config file, then default.
- Inspect what's set: `env | grep AWS_`; the values here are all fake, so nothing to redact.
- Use `unset` to clear a variable and fall back to the next level.
- `aws configure list` shows which credential source the CLI is currently using.
- `AWS_PROFILE` lets you keep an emulator profile and a real profile side by side.
- Re-export in every new shell, or add them to your shell startup file.

## Pitfalls
- Exporting in one terminal and running in another does nothing; variables don't cross shells.
- Forgetting to re-export after opening a new shell means commands silently hit real AWS or fail on credentials.
- Real credentials leaking into a lab shell; keep fake `test`/`test` scoped to the emulator.
