Q5.1 — First model call (30 XP)

Phase: Phase 5 — Bedrock + SageMaker

Concept

Bedrock gives you foundation models as an API. You don't manage GPUs or servers; you call a model like any other AWS service and pay per token. Models include Claude, Llama, Mistral, Titan, and Nova, and some require a one-time access request per region before they'll answer.

The two parameters that matter most for building instincts are temperature and max_tokens. Temperature controls randomness: 0 is close to deterministic and tends to repeat itself, while 1 wanders and varies from run to run.

max_tokens caps the length of the reply, which directly caps cost and latency, because output tokens are billed and slower than input tokens. Set it deliberately instead of leaving it at the maximum.

This quest makes you feel that difference by running the same prompt twice with different settings. It runs in a real sandbox where every call costs a little money, so note the model's per-token rate before you start.

Uses

  • Add a chat or generation feature to an app without hosting a model.
  • Summarize, classify, or extract structured data from text at scale.
  • Prototype an AI feature before committing to fine-tuning or a dedicated endpoint.
  • Compare models on the same prompt to pick the right cost/quality tradeoff.
  • Build deterministic pipelines (temperature near 0) or creative drafts (higher temperature).

Key info

  • Request model access in the Bedrock console if the model is greyed out in your region.
  • Invoke via CLI: aws bedrock-runtime invoke-model --model-id <id> --body '{"prompt":..., "temperature":0, "max_tokens":50}' out.json.
  • Keep the same prompt and change only temperature (0 vs 1) and max_tokens; compare both responses.
  • Pricing is per 1k input and output tokens and varies widely by model; output tokens cost more than input.
  • Note the per-model rate before bulk jobs; a loop of calls adds up fast.
  • Real sandbox only: Bedrock has no meaningful emulator, and every invocation bills.

Pitfalls

  • Forgetting the one-time access request, then wondering why the model errors.
  • Setting max_tokens very high "just in case," inflating both latency and bill.
  • Assuming temperature 0 is perfectly deterministic; it's near-deterministic, not a guarantee.

Done check

Paste both responses (truncated) + one sentence on what temperature changed.
