# Q1.2 — SQS queues + SNS topics (30 XP)

**Phase:** Phase 1 — First AWS Services

## Concept
SQS is a message queue: producers send, consumers receive, process, then delete. A received message isn't removed; it hides for the visibility timeout and reappears if you never delete it, which gives at-least-once delivery.

SNS is pub/sub: one publish fans out to every subscription. Wiring an SNS topic to an SQS queue is the classic fan-out pattern and the backbone of decoupled systems. Together, queues and topics let services work at their own pace instead of waiting on each other.

## Uses
- Buffer bursts of work so slow consumers don't drop tasks.
- Decouple a web tier from background workers.
- Broadcast one event to several independent consumers.
- Retry failed jobs safely with a dead-letter queue.
- Fan out notifications to email, Lambda, and queues at once.

## Key info
- Create a queue: `aws --endpoint-url=http://localhost:4566 sqs create-queue --queue-name dojo-queue`.
- Send: `aws --endpoint-url=http://localhost:4566 sqs send-message --queue-url <url> --message-body "hello"`.
- Receive: `sqs receive-message --queue-url <url>` returns JSON with a `ReceiptHandle`.
- Delete only after success: `sqs delete-message --queue-url <url> --receipt-handle <handle>`.
- Create a topic: `aws --endpoint-url=http://localhost:4566 sns create-topic --name dojo-topic`.
- Subscribe: `sns subscribe --topic-arn <arn> --protocol sqs --notification-endpoint <queue-arn>`.
- Publish: `sns publish --topic-arn <arn> --message "hi"`.
- Visibility timeout defaults to 30 seconds and is what hides a message after receipt.
- A dead-letter queue catches messages that fail too many times, for later review.
- FIFO queues add ordering and dedup, but standard queues are the default to learn.
- `get-queue-attributes` returns the queue URL and ARN you need for SNS or DLQ wiring.

## Pitfalls
- Deleting the message before processing it loses work if the consumer crashes mid-job.
- Re-running receive immediately while the message is still visible returns nothing; the timeout must expire.
- SNS stores nothing: publishing with no subscriber means the message goes nowhere.
