Q8.4 — Everything in Terraform via pipeline (50 XP)

Phase: Phase 8 — RAG Capstone

Concept

Reproducibility is the difference between a project and a demo. This quest takes everything from the data and API quests and expresses it in Terraform, then deploys it through the Phase 7 pipeline.

The real test is destroy and rebuild: you tear the whole system down, then let CI re-apply it, and the system comes back byte for byte, still answering requests. If anything has to be rebuilt by hand after a destroy, it was never really in Terraform, and that gap is tech debt with a demo date.

Pinning is what makes "byte for byte" true: exact model IDs, container image SHAs, and provider versions. Anywhere you write latest, you get "works today, mystery tomorrow." This is the highest-XP quest in the dojo because it is where the earlier phases prove they compose.

Uses

  • One source of truth: the whole system is described, reviewable, and versioned.
  • Disaster recovery: destroy and rebuild from CI proves the config is complete.
  • Environment cloning: spin the same stack up elsewhere from the same code.
  • Auditable change: every infrastructure change is a reviewed diff.
  • Interview signal: reproducible systems separate engineers from tinkerers.

Key info

  • Run Terraform from CI, not your laptop:

terraform init
terraform plan -out=tfplan
terraform apply tfplan
# break it on purpose:
terraform destroy -auto-approve
terraform apply -auto-approve
  • Pin everything: required_providers versions, model IDs, and image tags by SHA.
  • Store state remotely (for example S3 with locking) so CI and you share one state, not two laptops.
  • After the rebuild, curl the live endpoint again. Still answering with citations is the proof.
  • The pipeline needs permission to run plan and apply; scope that role to the resources it manages.

Pitfalls

  • Anything created by hand in the console. If it is not in Terraform, it does not exist and will not rebuild.
  • Writing latest for a model or image, so a rebuild silently changes behavior.
  • Keeping state only on a local machine, so CI applies against a different, blank world.

Done check

paste the destroy log + the CI re-apply log + the post-rebuild curl still answering.
